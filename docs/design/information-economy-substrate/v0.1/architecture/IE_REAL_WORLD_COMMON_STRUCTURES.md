## 3. Reconciliation: what actually recurs

The cross-domain inference is a compositional mechanism, not a claim that all institutions behave alike. It has twelve optional functions:

| Function | Generic inspectable operation | Distinction necessary for this repository |
| --- | --- | --- |
| Receive | Record a particular holder/custodian's actual eligible delivered fragment and acquisition point | Intended delivery and queue placement are not reception; receipt is not agreement |
| Record | Produce an attributed local record from eligible inputs, preserving its authored wording/terms and basis | Writing an account does not make its allegations actual |
| Route | Select a bounded destination/function and eligible payload | Naming a destination grants neither access nor knowledge |
| Screen | Apply an explicit supplied rule to a frozen eligible input set, recording result and reason | A screen result is not proof, guilt, entitlement or jurisdiction |
| Prioritize | Assign a bounded configured ordering value by an authorized processing act | Hidden world truth cannot influence actor-visible rank |
| Assign | Allocate work to a named eligible handler under a supplied task scope | Work allocation is not membership, normative delegation or full case access |
| Analyze | Make an attributed interpretation with explicit premises, assumptions and method revision | It may be wrong; new premises and revisions preserve earlier products |
| Investigate | Coordinate a request for additional acquisition or a separately admitted action | A task does not query omniscient actuality or manufacture evidence |
| Decide | Record a supplied-policy choice and its evidential basis | Decision recording differs from actual authority to perform an effect |
| Authorize | Record/validate a separately supplied actual standing over exact target/scope/time | An approver title, assertion or earlier assignment is insufficient |
| Refer / close | Deliver selected information onward, or end current processing with a reason | Referral does not convict; closure does not erase received information |
| Reassess | Open a linked review on a new acquired basis or explicit authorized reconsideration | No automatic rewriting of history or involuntary global stance revision |

Not every path contains every function. A shopkeeper can receive a count discrepancy, compare two acquired records and close it as unresolved. A compartmentalized institution can split intake, analysis, authorization and external referral. An informal neighbor may retell a fragment without creating a case. This is a reason to keep L1 useful without L2 and L2 useful without institutional identity baked into L1.

## 4. Architecture recommendations

1. **Reuse accepted KeyWrapping semantics.** L1 should realize receipt/acquisition/provenance and sealed projection over a separately approved native consumer. Do not introduce an alternative `organization knows` truth family. L2 composes L1 records and guarded changes; membership/standing remains externally owned. [P0 collision report](../preflight/INFORMATION_ECONOMY_TERM_COLLISION_REPORT.md).
2. **Use explicit synchronous transitions first.** A finite transition table can cover the recurring functions. Persist the input identity, actor, state witness, policy revision, exact payload, transition cause, outcome and publication order. Do not grant timers, callbacks, network listeners or workflow libraries mutation authority. The [organizational candidate](IE_ORGANIZATIONAL_PROCESSING_CANDIDATE.md) specifies this recommendation.
3. **Make delivered fragments the access boundary.** A referral carries selected copied contents or an immutable recipient-eligible content slice plus its exact receipt, never a magical full-case pointer. Byte deduplication can be internal; distinct deliveries and holder cutoffs remain distinct. An original-case trace is privileged unless actually conveyed.
4. **Treat memory as custodial availability plus individual acquisition.** Organizational record existence, permission to retrieve, actual retrieval and an actor's current assessment are different. Revocation can end present retrieval without erasing old acquisition. Unknown/missing/denied unacquired references need the same safe actor-facing behavior. [KeyWrapping P07-P13, P17](../../../keywrapping-substrate/v0.1/PERSPECTIVE_PROVENANCE.md).
5. **Make a bounded choice, not an institution simulator.** Charge per-item bytes, copied fragment bytes, recipients, queue entries, transitions, provenance edges, support work, full required history, query output and storage/reopen overhead. A count-only cap fails. Refuse prospectively before an acknowledged state becomes unsupportable. Do not convert queue pressure into guilt, priority into authority, or a TTL into deletion of evidence. [P0 boundedness](../preflight/INFORMATION_ECONOMY_BOUNDEDNESS_PREFLIGHT.md).
6. **Provide inspectable affected/unsupported status first.** Keep old analyses, stance and decisions; expose support loss only through an eligible view. Explicit reconsideration can produce a new decision or stance. Automatic belief revision, withdrawal of permission, reversal of payment and sanctions require independently supplied semantics and admission. ICD203 inspires inspectability; it does not settle game policy.
7. **Adopt no external workflow/domain library on this evidence.** Source research identifies semantic distinctions and small finite operations, not a need for an institution engine, rule network or external event store. A later reuse report/spike may alter the recommendation if it demonstrates concrete savings without hidden ordering or authority costs. Standard-library structures remain a provisional implementation proposal, not implementation performed here.

## 5. Unresolved owner decisions and required verification

Architecture acceptance must select the native consumer/successor boundary, finite profile and support horizon, minimal capability set and invalidation semantics. This report recommends options but adopts none. A toy profile's processing permissions must be expressly supplied without claiming Factions/Laws integration; real institutional duties remain external. Any native successor work needs separate implementation approval, exact source/profile identity, one installer, deterministic replay and independent qualification; frozen C1 remains untouched.

Required future verification should include: same-actor and split-function variants of the same path; false report leading to an attributed institutional decision while actual world truth remains correct; denied reader versus guessed missing case; stale assignment/authority; two referrals with a common source; cyclic referrals at their budget; exact retries versus genuine later retellings; closure and later acquired correction; queue-full and byte/work-full prospective refusal; historical cutoffs; and support invalidation without automatic enforcement. These are test obligations, not newly executed tests. The independent tester and auditor retain their own roles.
