Encounter owns actual identity/history/consequences; information is an attributed, acquired, access-qualified representation inside a future separately approved consumer. [Stage 12 boundaries](../../../../../contracts/SHARED_CONTRACT_DECISION.md), [KeyWrapping acquisition/projection constraints](../../../keywrapping-substrate/v0.1/PERSPECTIVE_PROVENANCE.md) under its [later acceptance correction](../../../economy-substrate/v0.1/phase-1/AUTHORITY_AND_PREFLIGHT_UPDATE.md), and the accepted [Economy boundary](../../../economy-substrate/v0.1/phase-10/GOVERNANCE_BOUNDARY_SUMMARY.md) govern. Repeated provenance cannot mint independent origin, and retained evidence cannot create actor knowledge. Economy D03/D10 support/consumer choices remain open.

The separately [accepted EA-C1/0.1.3 proof](../../../../../packages/encounter-core-c1/README.md) is bounded and non-social. Inspected [Core source](../../../../../packages/encounter-core-c1/0.1.3/eac1/core.py) enforces an immutable root profile, exact source identity, full-prefix replay/cost and safe prospective refusal. This is an existing reference envelope, **not an IE workload profile or authorization to expand it**:

| --- | ---: | --- |

Existing `profile()` accepts only these fields and values within their defaults; changing one changes profile identity. `data.py` separately bounds captured JSON depth, collection sizes, encoded expansion and scalar range; those defenses do not constitute rumor/access/derivation caps. Do not copy them as an approved IE schema.

For C1, let E be complete canonical root/history/optional-checkpoint bytes and P the larger of existing DB file length and staged writer page_count × page_size. Final reservation before COMMIT is `32*E + 1,048,576 + 4*P`; no SQL mutation follows that check. Declared memory accounting is `64*E + 67,108,864`; full replay/retry work is separately bounded. Post-write page/index/free-list/journal effects matter, not just payload lengths. A future IE data model needs a newly justified census; extending these constants without proof or bypassing source/profile checks is rejected.

The accepted source does not implement destructive history collection, infinite campaign capacity, social memory, asynchronous effects or a general successor loader. N01/N02 remain: process-crash COMMIT-entry/progress evidence is narrower than arbitrary mid-flush/power/device failures; same-version backend discrimination is incomplete. Existing 64-operation historical measurements are C1 evidence only. No IE runtime, memory, latency or city-scale capacity is measured here.

## 2. Growth model and attack surface

Symbols are analytical quantities, not adopted fields: A actors; C distinct attributed content items; T actual transmissions/receipts; P provenance links; D derived conclusions/support links; G explicit access grants; Q pending workflow items; H indispensable admitted history; V active projection/index entries. Payload size and number of source fragments are additional dimensions. No single count bounds bytes or work.

Naive global event replication costs at least A×world-event volume and violates acquisition isolation. A naive branching rumor of fan-out f through depth d can create 1+f+…+f^d transmissions. Independent derivation combinations may approach 2^n over n premises; all-pairs actor/record permission expansion may approach A×C. Cycles can make repeated scans nonterminating despite finite unique nodes. Full snapshot-per-transition retention can make aggregate stored bytes grow quadratically in admitted information volume; current C1 deliberately charges its complete prefix and has a finite ceiling. These are growth risks, not measured asymptotic performance of an IE implementation that does not yet exist.

| Growth path / adversarial workload | Bounded representation and lazy work to evaluate | Consolidation / cache strategy to evaluate | Overflow / pruning / evidence guard |
| --- | --- | --- | --- |
| **Rumor fan-out:** many recipients, repeated retells, loops, mostly failed sends | Represent actual permitted transmission once plus actual recipient fragment/receipt; explicit selected recipients and bounded work per operation/tick; no global broadcast scan or universal per-NPC event replication | Eligible per-holder views over shared admitted content may avoid payload copying; exact retry dedup distinct from genuinely later communication | Bound recipients, total receipts/bytes and pending sends. Refuse or defer before partial admission unless an approved atomic unit says otherwise. Never consolidate distinct utterances into nonexistent receipt or count holders as sources. |
| **Provenance depth / breadth:** deep chain, shared ancestor, circular distortion, forged source assertion | Immutable local links; iterative visited-set traversal; bounded depth/node/edge/byte work; immediate source and privileged actual lineage distinct from holder-known lineage | Cache privileged origin analysis with source snapshot/policy and validity; audience-specific explanation caches only after sealing | Truncated/unknown ancestry stays incomplete, never independent. Source assertions cannot replace actual lineage. A depth cap bounds a query, not permission to delete required causal edges or expose hidden sources/counts. |
| **Organizational duplication:** many offices, case copies, refer-back chains, attachments | Common admitted content with separate office/holder receipt/access references where selected; domain-neutral routing; selected referral fragments | Deduplicate immutable bytes where identity semantics permit; preserve different records/annotations, transmission acts and owner scopes; rebuild indexes | Bound office references, attachment bytes, onward destinations and queue items. Dedup by hash cannot establish truth, grants or independent origin. No automatic cross-org traversal or all-members knowledge. |
| **Derived-information explosion:** many premises/rules, recursive conclusions, alternative supports | Explicit eligible premises and versioned rules; bounded agenda and support edges; demand-driven inference instead of complete closure | Reuse exact qualified derivation only within its holder/audience/cutoff/policy context; reverse dependency index may be rebuildable if admitted support survives | Bound new conclusions, rule firings and inspected support edges per admission and total. No hidden truth premise, automatic social stance or domain-law implementation. Exhaustion cannot certify complete closure. |
| **Historical accumulation / staleness:** many corrections, obsolete accounts, receipts and formerly active cases | Separate current attention/index from admitted past accounts/support. Old record/receipt can remain historically true while content is stale | Drop/rebuild disposable caches; bounded current views may omit inactive items without claiming historical deletion; archival can change physical location only under an approved verified retrieval/support contract | TTL is a proposed attention/cache policy, not proof of safe history deletion. Preserve exact relevant terms, receipts, causal proof, source/policy identities, consequential exceptions, once-only identity and required external anchors. No collector is authorized. |
| **Access graph size:** many actors×records×roles with grants and revocations | Scoped explicit grants/relationships evaluated on demand; avoid materializing every possible pair; permissions distinct from possession/acquisition | Cache positive and negative decisions with audience, purpose, snapshot, cutoff and grant version; revoke invalidates dependent present access cache | Bound grants, memberships, recursion, inspected edges and cache bytes. Role-based evaluation cannot select Factions membership/collective authority policy; known parent/manager is no blanket access. Past learned information is not automatically erased on revocation. |
| **Reevaluation cascades:** one premise/source invalidation affects many conclusions/workflows | Reverse support references plus a bounded deterministic worklist; determine whether full support check is possible before certifying outcome | Coalesce same pending dependency work without losing original cause/order; resumable analysis only if approved with explicit incomplete state | Bound touched conclusions/edges/queued work and admitted invalidations. If budget insufficient, refuse before unsafe admission or mark dependent result unavailable/incomplete as approved; never leave stale support certified. Identifying loss does not automatically retract every NPC belief. |
| **Queries / diagnostics:** large explanations, search/ranking, unknown-handle probing | Audience eligibility before serialization/index exposure; bound scanned nodes, bytes and returned items; privileged diagnostic path separate | Cache keyed by full audience/snapshot/cutoff/purpose/policy context; discard on incompatible context | Omitted hidden nodes do not produce counts, gaps or failure reasons. A permitted result page cannot backfill truth. Query must not deliver, mutate or rebuild an authoritative state through a library. |
| **Workflow / rule order:** high-priority spam, referral cycles, automatic repeated work | Explicit transition cause, stable queue tie-break and finite rule evaluations; bounded due work; no asynchronous hidden callback writer | Projection queues and indexes must be reconstructible from admitted inputs if advertised as derived; persist non-rebuildable pending commitments deliberately | Need queue-full outcome and approved continuation/fairness policy. Priority does not create action authority; no automatic sanctions/refunds or domain-specific escalation from generic substrate. |

## 3. Caps requiring an architecture decision and later measurement

No new number below is configured or approved. Suggested test scales in §5 are independent stress inputs, not default limits. Numeric IE ceilings must be chosen for a named consumer/support horizon, with actual counters and evidence of admission/cold/retry/query fit. Open choices need not block starting an authorized architecture review; they do block claiming executable capacity or approving a design that depends on undefined overflow behavior.

| Proposed configurable budget | What must be charged | Required saturation behavior / decision |
| --- | --- | --- |
| Recipients/transmissions per admitted unit; per-holder and global receipts | Recipient enumeration, actual fragments, storage, provenance and retry identity | Select atomic batch vs explicit separate admissions. No partially acknowledged broadcast. |
| Content/attachment/string bytes; total history and indexes | Encoded/decoded payloads, full retained support, backend pages/journals and caches | Refuse before commitment if supported cold/retry state cannot fit. No byte-unbounded content behind a count cap. |
| Provenance query depth/nodes/edges/output bytes | Branching, cycle visits, hashes, source qualification and redaction | Produce scoped incomplete/unavailable explanation without fake independent sources or hidden graph-size disclosure. |
| Derivations per request/holder/global; rule firings/support edges | Alternative supports, nested derivations, versioned policy lookup, duplicate and cycle checks | No unrestricted logical closure. Explicit refusal or bounded approved continuation; preserve cause and partial-analysis status. |
| Grants/memberships per scope; traversal depth/edges | Group recursion and revocation propagation as well as successful authorization | No eager A×C expansion; fail safe on incomplete current authority check without unlearning past receipt. |
| Workflow queue length; due work per logical step; referral hops | Staging, scheduling, causal order, retry and full queue persistence/rebuild | Stop boundedly with an inspectable authorized status; no unbounded hidden backlog, starvation claim or automatic new clock tick. |
| Projection/cache bytes, entries and invalidation work | Positive/negative per-audience scopes, output encoding, query work and stale generations | Evict rebuildable material only; never resurrect cross-audience or future-cutoff data. |
| Simultaneous work/replay memory and physical workspace | Decoded/staged/verified originals, snapshots, DB/index/free-list/journal and recovery images | Verify before publication against the same immutable selected support profile; afterwards acknowledged head remains cold-readable. |

Domain rates, confidence formulas, prices/value of information, rumor probabilities, police thresholds, forgetting, Player-book permanence, organization membership and collective assent are separate open policy questions. Do not turn a capacity limit into one of these policies. A deterministic recorded seed would bound reproducibility, not work; seeded random fan-out still needs budgets.

## 4. Checkpoint loss, causal protection and retention interaction

Two inspected mechanisms must remain distinct:

| Scope | What is supported/proposed | IE consequence |
| --- | --- | --- |
| **Accepted C1 runtime** | Full mode-A root/prefix derivation; optional `checkpoints` never establish truth; malformed accelerator may be ignored and raw bytes still count. Required history/root/profile/meta/receipt checks remain exact. Checkpoint cap 8; no destructive collector. | An optional graph cache/accelerator can be dispensable only if verified admitted inputs and required support remain. Deleting or ignoring a projection cannot authorize loss of original receipt/derivation proof. New IE tables/fields are not automatically accepted by C1. |
| **C2.1 B0 reviewed documentary proposal** | [CHECKPOINT_CONTRACT](../../../encounter-core/c21-b0/v0.1.2/contracts/CHECKPOINT_CONTRACT.json) allows at most two exact whole eligible G9 checkpoint payload rows absent; surviving descriptors, exact mandatory prefix, original row commitments/heads and pre-reserved resources permit detached scratch reconstruction. Present corruption, descriptor or required proof loss is failure; physical read repair is prohibited. | This is neither installed runtime nor a general 'recover any missing provenance' rule. Do not apply C1's ignore-invalid behavior to these proposed committed rows or promote B0 reconstruction to executed proof. |

Both preserve required causal support; neither turns an accelerator into permission to discard the old evidence chain. Before any future pruning/archival proposal, enumerate promised historical questions, each required record/term/policy/source/identity/receipt, consequential derived support and the independently anchored acknowledged boundary. A derived conclusion that remains active or affects an action may protect premises no longer present in current attention. Repeated identical content can share bytes, but distinct acquisition times, holders and actual utterances cannot disappear merely because text matches.

An unavailable old source or unresolved support must be reported at its supported precision, not synthesized from world truth or summarized into eyewitness certainty. If a bounded explanation truncates, that truncation cannot make independent origins multiply. If support invalidation exceeds the chosen worklist cap, the system cannot label the conclusion fully supported pending unfinished analysis. If access is revoked, past acquisition/history is retained according to the eventual separate retention policy; a cache eviction is not forgetting. Any future retention/compaction guarantee needs owner-authorized semantics and independent proof; no safe infinite continuation is inferred in P0.

The causal graph needed by Core can be privileged while holder-visible provenance remains sparse or unknown. Retaining a true source is compatible with denying the recipient its identity. Do not solve boundedness by exposing every private source, per-holder proof clone, internal head, stable hash, source count or hidden truncation marker.

Measure at minimum: workload/candidate/root/profile and runtime/backend identities; operation/query/reload/retry elapsed time (repeat count plus median and maximum, percentiles only with adequate samples); process peak RSS and allocation trace as distinct metrics; exact canonical bytes, DB file/pages/free-list and journal/sidecar peak; number of nodes/edges/grants/receipts/derivations/rule firings/due jobs actually visited; queue depth; output bytes; and predicted work versus independent actual counters. Distinguish observational instrumentation from a production bypass. Retain raw measurements and all failed attempts; state overhead, machine and storage conditions.

No latency, memory target, campaign horizon, population size or benchmark PASS threshold is selected here. Architecture must declare a named bounded envelope and acceptance thresholds before a performance claim. Tiny synthetic correctness cannot substantiate city-scale operation, indefinite history or full durability certification.
