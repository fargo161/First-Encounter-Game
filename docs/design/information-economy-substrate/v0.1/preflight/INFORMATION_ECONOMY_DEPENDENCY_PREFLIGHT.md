## Meaning of decisions and evidence limits

**USE** means retain an existing verified facility in future design reasoning; **ADAPT** would recommend a separately reviewed boundary around a candidate; **BORROW CONCEPT** means study ideas without taking code; **OPTIONAL / HOLD** keeps a candidate available pending a demonstrated need and qualification; **REJECT** declines that candidate for this proposed substrate. These are recommendations, not dependency approvals. None of the external packages earns USE or ADAPT in this preflight.

Release dates below are primary registry evidence, not a promise of future support. Runtime declarations are compatibility claims, not executed Windows/Python 3.12.0 tests. Moving-branch files are labeled and do not substitute for exact release metadata. Transitive closure, source distribution contents, vulnerability advisories, wheels and licenses of every transitive component were **not** exhaustively audited; an unreviewed closure is a hold on adopting that candidate, not a claim that it is insecure. No throughput or city-scale readiness was measured.

## Preflight disposition and candidate-local holds

There is **no external dependency blocker to proceeding to an authorized architecture phase**: no external runtime package is necessary to state and review the architecture. None is approved for production. Architecture must first show where proposed informational state lives and how it respects the accepted Core's bounded, non-social status; this report does not supply a semantic installer or assume Core already accepts new record families.

Before any later package adoption, resolve the exact release artifact/hash, release-matched license files, minimal transitive closure/obligations/advisories, Python 3.12.0/Windows behavior, deterministic ordering, persistence boundaries, resource caps and fallback tests. D03's metadata mismatch is a local hold. D10's unknown license blocks its code reuse. Neither requires holding all preflight work because both can be omitted. An architecture requiring any library to become a second authoritative state/history/identity owner **would be a preflight blocker** and should be rejected instead of waived.

## Limited B/F validation, not Phase A specialist reports

**Evidence:** [ICD 203, analytic standards, pp. 4–6](https://www.dni.gov/files/documents/ICD/ICD-203.pdf) distinguishes source material, assumptions, judgments, source quality/currency and uncertainty, including reasons for changed judgments. **Inference:** reusable processing should retain sources/support and separate intake, analysis and authorization; it should not bake intelligence confidence scales or institutional thresholds into Level 1. One institutional source does not prove universal police/insurance/tax/gang workflow equivalence; that remains Phase A work if authorized.

**Evidence:** [Generative Agents, arXiv:2304.03442v2, 2023-08-06, §§4.1, 6.5.2 and 7.1.1](https://arxiv.org/html/2304.03442v2) uses retrieval over agent memory, reports retrieval/embellishment errors, and checks diffusion claims against the originating dialogue record. **Inference:** expose acquisition/support diagnostics and isolate higher-layer retrieval/reflection from admitted information. LLM-generated memory/importance is unsuitable as authoritative Encounter history. This paper does not validate a provenance-safe rumor engine, common-source independence or a scalable deterministic implementation.

Ensemble/CiF, FAtiMA, VelvetRP and AI Town were not expanded into Phase A evaluations; no code or license recommendation is made for them. Preflight does not require adopting any of those families.
