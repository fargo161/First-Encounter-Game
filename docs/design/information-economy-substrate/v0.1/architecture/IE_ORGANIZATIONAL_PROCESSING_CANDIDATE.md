# Information Economy: organizational processing candidate v0.1

Date: 2026-10-23, America/New_York. Specialist D, reconciled with B research. **Proposed architecture, not an accepted contract or runtime.** Gate P0 approval permits this design and selected disposable spikes. No implementation, migration, installed schema, production dependency or organizational authority has been created by this document.

## 1. Evidence and design boundary

The [primary-source investigation](IE_REAL_WORLD_COMMON_STRUCTURES.md) finds recurring receipt, recording, routing, screening, allocation, analysis, decision, referral and reconsideration mechanisms across materially different institutions. Sources also distinguish information from analytical judgment and investigation from settlement/authorization powers. That evidence supports reuse of functions; it does not justify copying police, insurance, tax or gang rules into Level 1.

Repository authority is stronger than analogy. [Accepted KeyWrapping perspective semantics](../../../keywrapping-substrate/v0.1/PERSPECTIVE_PROVENANCE.md), interpreted under the [later acceptance correction](../../../economy-substrate/v0.1/phase-10/GOVERNANCE_BOUNDARY_SUMMARY.md), already distinguish actual communication, receipt fragment, acquisition, stance, source assertions and private actual lineage. [KeyWrapping actual-authority/exact-performance semantics](../../../keywrapping-substrate/v0.1/TRANSACTIONS_COMMITMENTS.md) prohibit turning a record of a grant, promise or assignment into its successful actual performance. [P0 Core compatibility](../preflight/INFORMATION_ECONOMY_CORE_COMPATIBILITY_PREFLIGHT.md) establishes no installed social-capable native consumer. The proposed L2 must live inside the separately approved single-authority native boundary, never alongside frozen C1 as a second writer.

The responsibility split is:

| Layer / owner | Candidate responsibility | Excluded inference |
| --- | --- | --- |
| Encounter/Core | Admitted identities, actual state/history, logical chronology, effect admission, persistence and once-only publication | An L2 state engine cannot write its own alternate actual history |
| Accepted KeyWrapping semantics | Referents/handles, claim versus actuality, acquired fragments, actual/asserted/known provenance, projection, exact authority/terms/performance invariants | A new L1 family cannot override these through similar names |
| L1 realization | Typed attributed information, actual acquisition/receipt proof, contents/access distinction, explicit supports/derivations, temporal scope, safe bounded projection | Received content need not be true, believed, endorsed or independent |
| L2 proposed here | Guarded work records, explicit queues, function allocation, transition results, review/referral composition over L1 | Membership, normative standing, shared mind, case omniscience, automatic gameplay effects |
| Factions / owning authority | Actual membership, hierarchy, delegated standing and any collective assent policy if separately supplied | Job labels or L2 tasks do not create these facts |
| L3 domain policy | Fictional selection criteria, investigative/action predicates, coverage/tax/remedy/response policy | Research supplies no adopted legal rule, threshold or violent response |
| Higher consumer | Dialogue, BASED, personality, plans, presentation and separately selected stance revision | Queue order is not a universal social valuation or compulsory NPC behavior |

Economy F5 accounts can be inputs if actually acquired; F1-F4 meaning stays with Economy inside Encounter. All [D01-D11](../../../economy-substrate/v0.1/phase-10/RESIDUAL_DECISION_REGISTER.md) stay open. This proposal supplies neither coverage, tax liability, concealed-revenue benefit nor any economic effect from a referral.

## 2. Minimum logical objects: roles, not a production schema

Names below describe candidate logical responsibilities. They do not freeze JSON fields, tables, APIs or universal IDs. Every identity is qualified by the selected native producer/root/artifact and local kind/ID; a display label or case number never joins identities by itself.

| Logical object | Minimum inspectable meaning | Visibility / authority guard |
| --- | --- | --- |
| Custodial record | Immutable attributed content/version, actual local custodian, acquisition/creation basis, admissible content scope and history | Organization custody does not make every member a holder; existence and contents may have different eligibility |
| Case/work item | Named bounded processing purpose, exact selected input fragments, processing state/version, creation cause and current eligible handler assignment | Case existence, title, count, status and relation edges are information; denied users receive no automatic stubs |
| Function specification | Named capability such as intake, classify, analyze or review; permitted transition kinds and required supplied guard | No mandatory job object; many functions can map to one person, and one function to several people |
| Supplied processing scope | Native-admitted fixture authority identifying actor, permitted function, target/purpose/time and issuer/basis | This is an input/reference to actual authority, not L2 inventing membership or delegation. Self-asserted authority cannot authorize itself |
| Assignment | Exact actor/function/item/task scope, assigning actor and time, acceptance state if selected, and expiry/revocation basis | Allocation does not confer access, teach contents or extend the source's delegable powers |
| Queue entry | Destination/function, original enqueue cause/order, priority/due values under supplied policy, item witness and lifecycle | A queue's custody and an employee's read eligibility differ. A later handler must actually acquire the necessary fragment |
| Analysis / recommendation | Attributed output with its exact eligible premises, assumptions, interpretation/rule revision and support condition | Recommendation is fallible and gives no new power to execute it |
| Decision record | Attributed supplied-policy choice, scope, reason, acquired basis, actor and time | A decision to request/authorize an effect is distinct from the actual admitted effect and matched receipt |
| Referral / supplement | Explicit selected payload, authorized sender and destination, communication act, actual recipient fragment/receipt and privileged linkage | Sender's larger case does not become readable through the pointer; later case edits do not revise past deliveries |
| Transition result | Prior witness, exact request/retry identity, actor, guards/policy/source identities, bounded result and authoritative publication order | Rebuildable query indexes can mirror it; a separate workflow journal cannot certify or mutate actuality |

L2 needs no new `organization knows P` object. A question about organizational information must name a custodial record/function/queue and audience or a specific actor. An approved future collective-knowledge arrangement would need its own semantics; it cannot be inferred from this candidate.

## 3. Plain synchronous state transitions

Recommend a finite explicit transition table evaluated synchronously by the single native admission path. There are no automatic entry/exit effects, autonomous timers, recursive dispatch or user-provided callbacks. A rule evaluator may return a bounded proposal/value; only native admission publishes changes. The state labels below are proposed operational bookkeeping, not truth/fraud/guilt labels.

**Integrated first-profile reconciliation:** the director's bounded candidate selects only `queued -> assigned -> in_review -> decision_recorded -> closed`, with explicit `re_open` based on a new eligible receipt and a separate explicit referral delivery. Recommend that smaller state set for the first proof. Screening, priority and analysis can be attributed records attached to those states; they do not need separate state-machine nodes. The larger vocabulary in the table below explores how the common functions compose; it is **not** a requirement to implement all listed state labels, requests or policy choices. Unused waiting/suspension/general reconsideration paths remain deferred. The director proposes a new EA-IE/0.1 reference root in a new `packages/encounter-ie-reference/0.1.0` only after Gate A; this report creates no such package and grants it no present compatibility or authority.

Every changing request must supply its exact item/version or current authoritative witness, exact retry identity, actor/function scope, cause, selected eligible inputs, rule/policy revision where used and requested output. A repeated request with identical identity and contents returns the same admitted result within the chosen native retry contract; changed contents under the same identity are a conflict. These are obligations for the proposed successor, not claims that frozen C1 accepts these operations.

| From | Explicit operation | Required current guard and input | Result / outward meaning |
| --- | --- | --- | --- |
| No item | Intake | Actual eligible receipt or separately selected authored background basis; target custodian; required processing scope and capacity | New `received` item with copied exact eligible fragment(s); neither full source-case expansion nor a substantive finding |
| `received` | Record/screen | Actor has actually acquired needed inputs and current processing scope; supplied bounded classification rule/version | `screened` plus attributed classification/reason, or explicit unresolved result; information is not validated into world truth |
| `received` or `screened` | Route/enqueue | Exact selected destination/function and item version; authorized sender; bounded eligible payload, queue capacity | `queued` entry and routing cause. If a different holder needs content, a separate actual receipt must be part of the same approved atomic admission or separately completed before handling |
| `queued` | Assign/take | Current assignment/selection policy, eligible actor/function, processing scope, item witness; required separation rule | `assigned` with exact task; no expanded information grant or normative delegation |
| `assigned` | Begin/analyze | Handler has acquired specific inputs, current scope is valid, bounded method/version selected | `working` with an attributed analysis product or explicit information gap; no omniscient query |
| `working` | Request additional acquisition | Bounded named information/action request and request authority | `waiting` plus request record; completion requires a separately real acquisition/action result, not a presumed successful investigation |
| `waiting` | Receive supplement/resume | Actual supplement receipt, matching requested scope where required, current handler access and witness | `working` with newly acquired fragment(s); old input/analysis preserved |
| `working` or `screened` | Submit recommendation | Required eligible basis, explicit fallible reasoning/assumptions and supplied submit scope | `decision_pending` with attributed recommendation; no successful effect/authorization inferred |
| `decision_pending` | Record decision | Current decision scope, exact basis, policy version and any required separation/assent guard | `decided` with reason and selected disposition. Performing an external consequence requires a separately supported native command and matched result |
| Any active state | Refer | Current disclosed-scope authority and exact recipient, selected fragment, original context/time and bounded destination capacity | Existing item remains historical/active as supplied; a new referral and actual recipient receipt are recorded. Referral alone does not transfer responsibility or close the sender's item |
| Any active state or `decided` | Close | Current close scope, exact disposition/reason and unresolved obligations preserved | `closed`; no history deletion, learned-content erasure or exoneration/guilt finding |
| `closed` or `decided` | Reassess | New eligible acquired evidence or explicit reconsideration basis, current scope and retained old record | New linked review item in `received` (or explicitly supplied initial review state); old decision remains historical |
| Any state | Record support change | Exact named support change admitted under L1; all affected work within chosen bound or safe incomplete treatment | Existing record marked affected/unsupported in eligible inspection; its authored content, historical decision and stance remain unchanged |
| Active assignment | Reassign / suspend | Current authority, exact task/item, new handler/scope if any; payload acquisition separately satisfied | New assignment revision or explicit suspended processing; no silent transfer of learned knowledge |

The table is intentionally not a prescribed institutional sequence. An approved toy policy may skip screening or use one actor for intake through decision. It may reject transitions not meaningful in that configured workflow. A queue may contain a ready task while its recipient lacks content; then it remains unusable for analysis until acquisition completes. An authorized business record custodian may store a fragment without attributing belief to any employee.

**Failure is explicit.** Stale witness, invalid scope, unsupported transition, missing acquired basis or exhausted capacity creates no partial acknowledged transition. Actor-facing errors must follow the projection boundary; privileged diagnostics can distinguish reasons. Do not emit a more specific denied/hidden-source error merely because the designer can inspect it. If a valid prior receipt exists, a later failed assignment cannot retract that receipt; atomicity applies to the selected admission unit, not an invented rollback of history.

## 4. Queue ordering, logical time and persistence

The proposed first profile uses one bounded synchronous writer and no autonomous drain. A consumer requests at most the selected number of queue actions per admitted command; each committed consequence receives one native causal order. External arrival order is explicit input; thread scheduling, wall-clock time, filesystem order, hash iteration order and library callback order cannot decide simulation results.

For a named queue, use the integrated candidate's total selection key: `(-priority, dueNullLast, dueTick, originalEnqueueSeq, itemID)`, compared lexicographically, with missing due values after explicit values and a fixed normalized due value in the null case. Thus higher configured priority precedes lower priority, earlier explicit due time wins next, and original enqueue sequence plus the qualified native item identity resolves ties. Priority is a small finite configured integer/enum, not a global information value. All values and the queue/policy revision are persisted. Reprioritization is an authorized new act and preserves original enqueue order. No implicit library default is acceptable.

Queue selection uses only entries eligible for the named handler/purpose under the declared context. An actor-visible queue's order/count must not include hidden items; privileged global scheduling and actor projection are separate outputs. No fairness or starvation freedom is claimed by this key: a supplied policy can keep urgent work ahead indefinitely within the finite horizon. A later fairness rule needs an explicit logical-time/input basis and its own bound; no invisible automatic aging is selected.

Persist indispensable inputs and non-rebuildable commitments: exact delivered fragments and acquisitions, immutable records/analysis, authority and policy/source identities, assignment versions, original enqueue cause, priorities/due values, queue transitions, referral receipts, support edges, decisions, close/reassess links, retry identity and native publication order. Persist no authoritative library object, executable callback or Python object pickle. Rebuildable indexes/caches can be discarded only when exact reconstruction is supported from retained admitted inputs. Querying or rebuilding an index must not advance time, generate receipts, process tasks or repair canonical history.

Reload must reproduce the same pending entries, selection order, historical views and once-only results. A later policy revision affects only separately admitted prospective work; it cannot reinterpret the recorded past unless a new explicitly scoped review does so. A closed item's history and a still-live duty/referral need can protect its records from deletion. No TTL, archive, compaction or forgetting mechanism is selected.

## 5. Actual referral fragments and compartments

Illustrative fixture, with synthetic identities and supplied test permissions only:

1. A business custodian has record R1 containing a discrepancy, the clerk's account and a private supplier identity. The tax-like reviewer has no R1 access and does not know the supplier.
2. An authorized sender selects F1: the discrepancy and clerk's quoted account, preserving the selected content's event-time qualification and actual delivery time. F1 includes only the source assertions and provenance the sender is permitted to disclose. Selection does not rewrite true privileged lineage.
3. The native admission records the actual communication and the receiver's particular F1 receipt. The receiver's work item contains exactly F1 or a reference to that exact immutable delivered item/version plus the eligible projection, not an expandable R1 object. An internal privileged source link supports audit, without making the supplier identity, R1 title, undisclosed attachments or original case counts actor-visible. This is a semantic copy of the delivered information; it does not require duplicate stored body bytes.
4. The receiver may screen F1 under supplied toy criteria. Its classification can be wrong. It may request more information, which teaches nothing until a qualifying real response is acquired.
5. A later correction F2 is a new supplement requiring actual delivery. Editing R1 or closing the business's case does not retroactively alter F1, silently deliver F2 or make the receiver forget F1.

Byte storage can share immutable content fragments internally after exact slice identity is fixed. Logical deliveries remain recipient-specific and historical; physical deduplication grants no access, source independence or identity association. A receiver who knows only that a case exists cannot use its handle to enumerate hidden child documents. Two organizations referring the same source chain provide two transmissions, not necessarily two independent witnesses. A referral back to the original organization can be a real later communication; loop limits prevent unlimited propagation without erasing that occurrence.

## 7. Boundedness and support obligations

The director's proposed finite first proof has 64 total admitted mutations across the world, 16 actors, 4 organizations, 16 cases and 32 tasks; each operation permits at most 4 recipients and 8 queued changes. These are candidate proof ceilings, not a campaign promise, policy adoption or authorization to implement. The integrated candidate must additionally bound bytes, work, memory, workspace, retained support and cold/retry/query obligations. This specialist recommends charging all dimensions, then applying prospective refusal without compaction. L2 adds the following census obligations to L1/native costs:

| Dimension | Must charge | Safe proposed limit behavior |
| --- | --- | --- |
| Work items and queues | Every pending and historically indispensable item/entry; entry/index and transition bytes, not only active counts | Reject a new enqueue/intake before publication if its required support or future cold/retry fit is unsupported; keep existing queues readable |
| Payload and recipients | Encoded/decoded fragments, attachments, visible metadata, every real recipient receipt and internal eligible-slice descriptor | No hidden unbounded attachment behind a reference; no acknowledged half-broadcast. A one-recipient referral suffices for the smallest proof; the integrated profile can permit bounded batches up to its explicit cap |
| Assignment/access | Current and protected old scope/grant/assignment identities, required policy checks and traversal work | Recheck current guards at use. Incomplete access evaluation cannot certify authorization; it does not erase learned material |
| Transitions and logical time | Per-command changes, original causes, queue scans, rule work and required due-work accounting | No recursive auto-transition cascade or automatic tick to drain backlog. A queue inspection remains a read |
| Referrals | Destinations, exact fragments, lineage links, referral chain/query work and repeated genuine acts | Bounded explicit send; cycle/depth exhaustion remains incomplete, never independent corroboration or permission to skip actual receipt |
| Support invalidation | Affected item/conclusion enumeration, reverse edges, new status bytes, query exposure and follow-on work | First profile identifies affected/unsupported only. Holder-visible support changes require the holder's actual eligible notice; private discovery cannot update their knowledge implicitly. Reject unsupported publication or use the main candidate's explicitly safe incomplete status; never certify stale support while a cascade is unfinished |
| Retention | Basis for live tasks, past decisions/consequences, precise terms, actual receipts, source assertions/lineage, retry identity and required historical questions | Closure/TTL/cache eviction cannot delete indispensable inputs. Stop supported continuation before support loss; no infinite-campaign claim |
| Projection/inspection | Eligible scans/output bytes, contexts, cutoffs, ranking and private diagnostics | No hidden-entry counts, priority effects or support-loss explanation leaks. A full diagnostic save is privileged |

The primary-source evidence suggests workflow relevance, not a performance target. This report measures no throughput, memory, disk or organization scale. C1's 64-operation profile is not a proposed institutional capacity. Numeric L2 limits and accounting/replay proof belong in the integrated candidate and later independently tested implementation work.

## 8. Minimum capability recommendation, deferrals and owner decisions

Recommend a first implementation proposal containing only: L1 attributed fragments/receipt/provenance/access qualification; immutable recorded inputs and explicit support; one finite synchronous work-state table; guarded assignment; explicit total queue order; one-recipient selected-fragment referral and supplement; reasoned closure/linked reassessment; inspectable affected/unsupported support status; historical/privileged inspection; and native replay/retry/capacity obligations. A tiny organization and compartmentalized organization should run through the same mechanism under different explicit toy policies.

Defer automatic stance revision, psychological forgetting, probabilistic rumor propagation, collective assent, general membership/hierarchy, automatic domain-law decisions, sanctions, payout/tax calculation, timers/async workflows, recursive rule closure, a general workflow DSL, distributed messaging, real institutional APIs, data migration/compaction, playable content and Unity. Any proposed external library needs demonstrated net savings over this table; nothing here requires a production workflow dependency.

Gate A owner decisions remain: approve one native consumer/successor proposal; approve exact finite profile/retention obligations and safe refusal semantics; adopt the L1/L2 semantic allocation and minimal capabilities; choose affected/unsupported inspection versus stronger automatic stance revision; select any dependency; and separately authorize an exact implementation/proof work order. This report recommends inspectable invalidation and no workflow library, but does not make those owner decisions. Independent tester and adversarial auditor must evaluate the integrated candidate separately. **Stop at Gate A.**
