1. Extract `Encounter_M3_Checkpoint.zip` into a new folder.
2. Open a terminal in the extracted folder containing this README.
3. Run `python scripts/serve-m3.py` with Python 3 installed.
4. Open the printed `Local: http://127.0.0.1:.../` address in a browser. Keep the terminal open while playing; Ctrl+C stops the helper.

Direct file/double-click launch was not verified; use the tested server method. The separate `dist/index.html` is historical M2.

**Save run** supplies complete JSON and a download. Saves are manual; there is no autosave. To use a fixture, open its JSON in a text editor, copy all text, choose **Open run**, paste it and select **Load this run**. Keep your original file.

Legacy/M2, altered and incompatible saves are refused without changing the current run. No old-save conversion exists.

The **Author inspector** includes hidden authored facts for diagnosis; ordinary gameplay uses filtered views. Inspector refresh, replay and skip are non-mutating. It is not a player-information surface.

## Rebuild and rerun

Use Node 24+ for build/tests and Python 3 for evidence/packaging. No npm dependencies are needed.

```powershell
node scripts/build-m3.mjs
python scripts/check-m3.py
```

The check helper builds, computes source identity, verifies preservation, runs the M0 audit, all builder tests, unchanged independent M1/M2 tests and generated-evidence validation. It supplies the independent M2 root/evidence environment bindings. `npm test` runs builder tests alone. `npm run build:m2` is historical compatibility.

Keep the external `Encounter_M3_Checkpoint.identity.json` beside its ZIP. It identifies the archive and every member by bytes/SHA-256. From the extracted folder, verify it with:

```powershell
python scripts/verify-checkpoint.py ..\Encounter_M3_Checkpoint.identity.json
```

Freeze tooling refuses existing destinations and old checkpoint labels. Rebuilding/checking an extracted review copy may update its logs; it cannot alter the frozen archive.
