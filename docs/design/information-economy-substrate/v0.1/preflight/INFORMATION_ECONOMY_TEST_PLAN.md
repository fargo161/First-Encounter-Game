## 2. Independent harness and common oracles

After an owner-approved architecture and separately authorized implementation, the independent tester must inspect the actual candidate identity and write fixtures/oracles independently of Builder expected outputs. Synthetic setup may stipulate abstract occurrences and actors without adding Steal/Kill or institutional actions to the accepted vocabulary. A real fixture action is available only when its eventual consumer supports that action. Do not modify C1's frozen source to make it accept social fields.

For every test, retain setup, admitted inputs, expected meaning, actor-visible outputs, privileged causal trace, before/after authoritative boundary, candidate/profile/backend identities, logs, and the test's PASS/FAIL/NOT RUN result. Read-only queries must not admit operations, advance time, deliver information, repair admitted semantic data or silently widen access. Independently qualified native backend recovery before a verified query is distinct from a projection performing authoritative repair; C1's SQLite rollback recovery is not a new gameplay admission. Compare state at the proper boundary: a legitimately recorded transmission or later authorized consequence can add history, but the false proposition cannot replace the event being discussed.

Common controls for all A–L:

1. **Acquisition and authority:** name each actual observer/recipient, received fragment, channel, cutoff, content source and actor/object authority. Intended audience, membership, record existence and mere event linkage do not establish receipt. No unadmitted simulation side effect may create a consequence.
2. **Sealed views:** run authorized holder, other holder, uninvolved actor and privileged diagnostic queries. Metadata, labels, IDs, source counts, search, error details, sort order and caches must respect the same boundary as content. For an unacquired guessed reference, hidden-existing/denied/missing controls have the same actor-visible unavailable behavior; privileged diagnostics may distinguish them. Do not infer performance side-channel immunity without its own declared threat model and evidence.
3. **Persistence:** commit the supported acquisition/workflow operation, close all instances, reopen in a fresh process, query with the same audience/cutoff, and compare exact selected state/order/provenance. Rebuild or discard optional projections and repeat. An exact retry produces its original receipt and zero extra delivery/derivation/economic effect. A new utterance is a genuinely new occurrence even if text repeats.
4. **Determinism:** replay the same admitted sequence from the same root/profile/policy identities; compare semantic result, ordering and safe projections. Vary dictionary insertion/hash seed, graph insertion, cache warmth and process scheduling where relevant. Reordered causally ordered inputs need not produce the same history; expected order changes must be explicit. Any random choice requires an approved algorithm/version and recorded seed/input. Wall-clock time and model output are not hidden decision inputs.
5. **Negative non-mutation:** refused/unsupported/over-budget proposals leave the prior acknowledged boundary readable and perform no partial delivery. Query unavailability never becomes proof of content falsity. If publication is uncertain, reconcile according to the selected contract before retry; do not claim zero physical writes merely because semantic admission failed.

## 5. Persistence, migration and rollback qualification

The architecture must first choose and justify the persistent information that counts as admitted state and the projection that is rebuildable. No runtime storage schema or migration is selected in P0. Do not add tables to accepted C1: its loader checks an exact four-table inventory and pinned root/source/profile. Its existing operation set is non-social. A new compatible consumer cannot be assumed merely because both use Python/SQLite.

Planned persistence matrix: successful commit/close/reopen; exact duplicate retry; conflicting key/result; stale witness; proven refusal; uncertain publication/reconciliation; boundary commit/reopen; optional projection missing/corrupt; indispensable provenance/policy/source/history missing; unsupported source/profile/backend; read-only diagnostics; multiple audience/cutoff cache rebuilding. Compare acknowledged heads/receipts and raw stored bytes at the correct semantic boundary. Actual platform faults and partial COMMIT tests require their own supported model and disposable data.

C1 optional accelerators can be absent or ignored invalid while full replay remains mandatory; their bytes are still charged. C2.1 B0's proposed loss contract instead permits only specified whole G9 payload-row absence, exact scratch reconstruction, surviving descriptor/commitments and original anchors; present corruption is not eligible absence. Keep those tests separate. Neither contract licenses deletion of required information lineage, old receipts, causal proof or newly consequential support. No read repair and no alternate older head are accepted substitutes.

If an eventual architecture requires migration, independent tests must cover: exact version/source identification and explicit compatibility refusal; byte-preserved backup of original; disposable forward transform with independently checked semantics/audience scope; interruption before and during publication; rejection of partial output; rehearsed restore of source plus compatible reader; no dual active writer; exact identity/history/receipt preservation where claimed. If lossless reversal is impossible, require an approved rollback boundary and proof of retained source rather than claiming an inverse. Until then migration tests are **NOT APPLICABLE TO CURRENT P0 / NOT RUN**. C1 0.1.2-to-0.1.3 compatibility is not a provided migration.

## 6. Ordering, limits and dependency failure qualification

Use the [boundedness preflight](INFORMATION_ECONOMY_BOUNDEDNESS_PREFLIGHT.md) benchmark matrix. For each configured cap, independently compute the tested workload and inspect limit-minus-one, at-limit and plus-one behavior, combined limits and cold recovery under the same profile. A refused large request can coexist with an admissible smaller request. No cap increase, hot-cache bypass, false complete support analysis or partial acknowledgement can hide overflow.

Stable ordering needs an explicit logical-time key and tie-break over admitted identities/sequence, versioned rule order and deterministic queue/graph traversal. Run same-input trials with distinct process/hash seeds and construction orders without shuffling the causal input history. Stop/restart an analysis or queue between bounded slices; verify approved continuation is once and does not change published order or leak protected ordering metadata. Lazy queries must obey budgets too.

Any later optional graph library, PROV export or UI diagnostic must be removable/corruptible without altering admitted information, truth, recipient sets, rule order or retry behavior. Test dependency absent, unsupported version and derived-cache format failure against a specified fallback. If there is no equivalent fallback, the optional feature is unavailable with safe diagnostics; it does not silently become a different authoritative calculation. Workflow/rule-library callbacks require a separate pure-result/admission boundary and a reference oracle. Required dependencies fail explicitly before dependent admission rather than claiming graceful support they cannot supply.
