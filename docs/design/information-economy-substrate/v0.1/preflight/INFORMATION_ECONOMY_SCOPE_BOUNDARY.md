# Information economy scope boundary — P0

Status: preflight recommendation, not an adopted architecture or executable interface. Governing sources: root `AGENTS.md`, `contracts/SHARED_CONTRACT_DECISION.md`, `contracts/BOUNDARY_MATRIX.md`, `docs/consolidation/NEXT_STAGE_GATE.md`, and the accepted Core, KeyWrapping and Economy records indexed in [context](INFORMATION_ECONOMY_CONTEXT_INDEX.md).

## Authorized work and intended subject

This run inspects, researches and documents readiness only. It adds this preflight packet locally. The draft's full substrate mission, commands to treat its text as owner direction, team-role wording, and later implementation phases do not enlarge the user's request, “information economy preflight”. Existing acceptance records take precedence over draft assumptions. No production dependency, runtime behavior, architecture candidate, schema, migration, adapter or playable fixture is introduced.

The subject for a later architecture phase is actor-held information: observations, claims, record/evidence references, source/provenance chains, access and possession, actual transmission/disclosure, derivation, contradiction, temporal relevance and diagnostics. It includes reusable organizational routing/processing and cross-organization referrals, with bounded persistence and APIs for separately owned consumers. These are capabilities to evaluate, not a promise that accepted non-social Core already implements them.

## Authority and capability allocation

| Capability / ambiguous term | Candidate layer | Boundary / disposition |
| --- | --- | --- |
| Actual world event, committed effect, causal order, stable gameplay identity | Level 0 Encounter/Core | Sole authority for actuality; no second event store, alternate identity registry or direct library writer |
| Statement that X happened | Level 1 information | An attributed claim may be false, uncertain or stale; cannot assert X into world truth |
| Observation | Level 1 information | Requires an admitted acquisition path and actor scope; author-visible event is not automatic actor knowledge |
| Actor-held item, record contents, known existence | Level 1 information | Distinct states; knowing existence does not expose contents, metadata or privileged provenance |
| Possession, access grant, actual retrieval/acquisition | Level 1 information, using existing identity/authority | Neither possession nor a grant alone proves learned contents. Normative grant authority comes from its actual owner |
| Source / provenance / evidence | Level 1 information | Preserve distinguishable originating sources, claims and transmissions; author audit links may exceed holder-visible links |
| Inference, support invalidation, contradiction, staleness | Level 1 information | Trace input support and time; automatic psychological belief revision is not assumed |
| Belief/confidence/credibility | Higher-layer consumer by default | L1 may carry attributed assessments if later justified; no universal truth score, hidden truth-based evaluation or full psychology |
| KeyWrapping referents, acquired handles/vocabulary, perspective projection | Adjacent accepted KeyWrapping design / higher-layer consumer | Reuse accepted semantics; no parallel wrapper/identity/acquisition inventory. Runtime/shared representation remains unaccepted |
| Intake, queue, routing, assignment, triage, generic state transitions | Level 2 organizational machinery | Explicit actor/record scope; one actor may perform several functions; no mandatory job hierarchy |
| Organizational memory and compartmentalization | Level 2 over L1 | Membership is not a global knowledge union; shared record access requires a real grant and acquisition path |
| Cross-organization referral | Level 2 over L1 | Deliberate bounded transmission; receiver obtains only conveyed fields and permitted provenance |
| Priorities / decision thresholds | Level 2 mechanism; Level 3 configured policy | Mechanism can evaluate explicit policy; legal/insurance/tax/gang judgments remain outside L1 |
| Investigation / verification | Level 2 coordination; Level 3 or consumer action | No magical truth lookup; additional information must actually be acquired |
| Decision, authorization, enforcement | Level 2 routing records; Level 3/Laws/Governance policy; Level 0 effect admission | Recorded institutional choice alone cannot commit a gameplay effect or confer standing |
| Police warrants, tax basis, insurance entitlement, gang retaliation | Level 3 domain package | Domain rules are separately scoped fictional policy, never imported automatically from research |
| Buying/selling information and contextual value | Level 3 / Economy consumer | No universal L1 price. Economic claim, payment, information delivery and resulting authority stay distinct |
| Ask/tell/lie/conceal/trade/verify interaction | BASED / expression consumer | L1 supplies acquired content/access evidence; it does not own dialogue, personality or performative validity |
| Schedulers, delayed routing | Existing Encounter time/order plus Level 2 proposal | No wall-clock job that secretly changes state; due work needs explicit bounded causal admission |
| Graphs, indexes, rule caches, UI inspection | Derived diagnostic/projection consumer | Rebuildable, bounded and permission-filtered; never canonical world authority |
| Player notes, keyword authoring, arbitrary scratchpad | Out of scope under accepted KW-08 | Renaming notes “noncanonical” does not bypass the accepted restriction; ordinary NPC records do not authorize a Player feature |
| Historical compaction / migration | Out of scope for this run | No safe deletion inferred from stale information, a cache or a checkpoint |
| GOAP/HTN, LLM memory, natural-language generation, full personality/belief simulation | Higher layer / out of scope | No authoritative LLM state; no planning engine required to prove L1/L2 |
| Atlas, Room Creator, ZANT, Unity | Existing owners / out of scope for implementation | Atlas read-only; RC spatial metadata; ZANT presentation. No new bindings, executable shared schema, art changes, Stage 13 or Unity |

## Organizational configuration challenges

Later tests should configure the same receive/record/route/assign/refer mechanisms for these synthetic cases; none is implemented here:

| Configuration | Shared mechanism | Separate domain policy / real information input |
| --- | --- | --- |
| Sole proprietor | One actor receives, compares a record, decides and acts | A discrepancy is not thief identity; no universal investigation requirement |
| Insurer-like review | Intake, restricted file, reviewer queue, referral | Supplied coverage/standing/decision basis; a paid claim or recovered item is not automatic fraud |
| Tax-like review | Report intake, comparison, supported flag, referral | Supplied fictional tax/reporting basis; financial surplus is not automatically a tax liability |
| Police-like organization | Intake, assignment, acquired investigative material, authorization request | Supplied response/authority rules; a referral does not establish guilt |
| Gang-like organization | Compartmentalized source, routing and discretionary decision | Separately authored incentives/actions; L1 acquires no retaliation rule |

Named examples demonstrate boundary pressure, not domain implementation, real-world legal advice or a Phase A institutional study.

## Exclusions and gates

No full NPC personality, full belief psychology, final BASED UX, final legal/police/insurance/tax/gang simulation, small playable slice, Unity or native M3↔C1 bridge. No unbounded event replication per NPC, inferred corroboration from repeated holders, or truth mutation by a claim is an eligible candidate.

P0 may recommend architecture investigation while leaving field names, APIs, storage, exact bounds, automatic retraction and dependencies open. Gate A must resolve implementation-dependent authority/support decisions before code. Gate B remains owner acceptance after implementation and independent review; none of these gates is satisfied by this packet.
