## Interface/contract freeze before the first new world

M0 must specify exact closed record/request/result/state fields, native version/hash tags, callback-free operation grammar, source/policy/profile census and errors in the new package's local contract documentation and validators. These technical details must implement, rather than reopen, the approved semantic meanings. Any change to an owner-level GA decision returns to review before code that depends on it. No universal cross-package wire format, runtime adapter or schema migration is included.

Native intents cover `AssertClaim`, `Observe`, `Deliver`, `AcquireRecord`, `Derive`, `QualifySupport`, `DeclareStance`, `SetRecordAccess`, `OpenCase`, `RouteTask`, `AssignTask`, permitted case transitions/decision/referral, root-controlled `AdvanceTime` and the separately authorized L0 reference effect. Exact atomic units and no-acquisition implications are candidate §8. The neutral effect is fixed `+1`, once per `(decisionID,referenceEffectSlot)` with a retained native consumed credit; a new operation ID cannot double-apply that decision, while original exact retry returns the original receipt. Intents are trusted technical inputs, not a new unrestricted Player authoring API. First proof does not expose an unexpressed Player stance store.

Pin this compact implementation trace in M0: (1) producer `AssertClaim`, one producer receipt; (2) authorized `Refer` to receiver container plus optional receiver-authorized case/task creation and a minimal dispatcher existence notice, two explicit targets; (3) `AssignTask`, one named handler existence notice including the authorized actor-local record/selected-fragment existence handle required for subsequent lookup, without sealed original-file backlinks; (4) handler `AcquireRecord` of that receiver-held slice/version under its separately supplied access grant, one content receipt; (5) start review; (6) record a policy-based decision from the actual acquired fragment; (7) separately admit the authorized L0 reference effect/consume decision credit; (8) close. These are eight semantic admissions, not one per internal notice; target receipts/task changes also count toward128/4-per-unit/32/8-per-unit limits. No content acquisition is implied at2/3; source claim truth remains unchanged. A later acquired new-evidence receipt can explicitly reopen the same case with a new linked task/enqueue age, retaining the old closed task/decision/receipts. Closed tasks still count toward32; reprioritization never resets existing task age. This is a prospective trace, not an executed fixture.

Use full coarse private witnesses initially. A trusted preparer captures all relevant native state; neither actor queries nor dialog/UI receive the witness/head/global hash. Semantic intent ≤8 KiB, total prepared request ≤160 KiB and state ≤128 KiB are distinct. Root/history/receipt/result/storage escapes and every staged pass count too. A smaller serialized current state does not license dropping required historic support.

Policy expressions are finite, root-pinned data with a small explicit whitelist (typed literals/eligible fields, equality/order comparisons, bounded AND/OR/NOT and three-valued missing inputs); proposed maximum 32 expression nodes and depth 8. No attribute access/calls/import/regex/custom resolver/host clock/LLM. The authority validator can inspect actual grants; analysis rules receive only the holder's already-authorized immutable inputs. Rule output is a proposed recorded decision or explicitly bounded derivation, never a direct writer. Complete JSON structural limits are candidate §12: depth24, object keys128, array members256, value nodes32,768, strings4,096 UTF-8 bytes (fragment512), integer ±(2^53−1), no duplicate keys/floats/nonfinite values; pre-decode lexical bounds must be enforced, not just post-parse checks.

**Admission feasibility gate:** Before COMMIT, scratch-rederive the actual prospective prefix from the writer transaction and verify exact prospective head/state and complete ≤20M cold cost; reserve/check the worst exact retry including the oldest acknowledged operation ≤20M and the promised current/historical holder-page/boundary/receipt queries within their selected phase budgets. Charge every parse/validate/serialize pass and bounded full-key sort cost. Own admission≤40M and encoded prefix≤8MiB alone do not prove this; three 8MiB byte passes already exceed20M. If any future required path does not fit, refuse before acknowledgement, without cap increase, pruning or older-head fallback. Integrated minimum usefulness requires every A–L minimal world and one explicit16-admission mixed sequence to complete with fresh-process reopen, promised queries and oldest retry. Exact recipe/oracles are part of M0/M4, not deferred after acceptance.
