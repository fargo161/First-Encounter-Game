# Information Economy term collision report

Date: 2026-10-23, America/New_York. Status: PREFLIGHT ONLY; semantic compatibility findings and recommendations, no installed vocabulary/schema. Evidence IDs refer to the [context index](INFORMATION_ECONOMY_CONTEXT_INDEX.md). Roles C/G.

## Principal finding

The draft's proposed Level 1 overlaps substantially with the owner-accepted KeyWrapping design and existing legacy knowledge implementation. “Information Substrate owns information” cannot become a second truth, identity, acquisition, provenance or audience-projection authority. A future architecture should identify which existing semantic responsibility is being realized or extended, then name each new organizational responsibility separately. No rename or new subsystem boundary is adopted here. E13–E21.

## Adversarial reconciliation controls

These are future architecture review obligations, not executed software tests:

1. **Common-source and circular rumors:** actual A→B→C→A hops and A→B/A→C fan-out remain distinct communications but one supported originating basis where appropriate. Do not count holders, quote nodes or graph paths as independent corroboration. The actor may know less lineage than the privileged audit. E16 P04–P06.
2. **Phantom event and mistaken identity:** a false accusation or wholly invented insurance loss keeps real communication/acquisition history without creating guilt, identity merger or a loss event. E16 P01/R04/R11; E21 F5.
3. **Restricted record and access loss:** a holder can know “a report exists” without content access; revocation changes present access while preserving any actual earlier receipt. Record destruction does not unlearn content or guarantee a replacement clue. E16 P08/§8; E19.
4. **Staleness and unsupported derivation:** retain the old claim, its validity scope and later correction/support change. Neither current truth nor current cache can rewrite an earlier audience view. Identifying withdrawn support need not automatically impose a universal belief-retraction algorithm. E16 P05/P15–P17.
5. **Institutional referral:** sender's complete case file is not the delivered referral. A receiver gains only the actual transmitted fragment and eligible asserted provenance. Hidden originals, other compartments and authentic source lineage remain sealed unless acquired. E16 P02/P04/P10; E19.
6. **Metadata attack:** equal authorized outward inputs must not vary in search counts, labels, ordering, hash fragments, error detail, graph degree or revision gaps when only hidden facts differ. A provenance graph is not actor-safe merely because its node contents are masked. E16 P11–P14; E13 §2.5.

## Preflight disposition

No observed collision requires changing accepted Core or KeyWrapping to finish preflight. Before implementation, a candidate must explicitly map general acquisition/claim/provenance responsibilities onto the accepted design baseline, select a bounded executor/persistence proof and leave Laws/Factions/BASED policy above its authority. The high-risk choices are semantic ownership and audience sealing; field/table names and external graph layouts remain unselected. Architecture review can resolve those choices without treating existing design-only records as installed contracts. Stop at Gate P0.
