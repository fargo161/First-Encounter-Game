## Recommendation

Recommend **zero new external runtime dependencies for the first bounded implementation proposal**. Use existing Python standard-library facilities to express the smallest reviewed provenance/support/workflow mechanism inside a separately approved native admission/persistence boundary. This is a proposed selection for Gate A, not permission to implement or extend frozen EA-C1/0.1.3. Standard-library-only does not remove the need for semantic, identity, replay, disclosure, capacity and recovery proof.

Retain NetworkX and `prov` as optional later developer graph/interchange tools. Keep one workflow library and `rule-engine` available only if a demonstrated authoring requirement exceeds explicit transitions/predicates. Defer RETE and full truth maintenance until measured workloads and approved behavior justify them. Reject a second canonical `eventsourcing` application/store. A library becomes worthwhile when it removes substantial required machinery **after** its boundary/qualification cost, not merely because its terminology resembles the feature.

## What cannot be outsourced

These are project-specific obligations regardless of candidate library. The proposed minimal mechanisms below are **inferences/recommendations**, not installed schemas or approved public APIs.

| Required responsibility | Minimal mechanism to evaluate | Irreducible custom work / evidence |
| --- | --- | --- |
| Distinguish world occurrence, proposition, source assertion, acquisition and stance | Explicit immutable native records and qualified references | KeyWrapping overlap, allegation without real event, receipt vs belief, truthful privileged lineage vs acquired lineage; no graph package defines these meanings |
| Common-source/circular provenance | Directed typed links, bounded iterative traversal and explicit incomplete result | Grounded origin/support semantics, distinct utterances, false origin assertions, unknown ancestry and holder redaction; holder count is not source independence |
| Unsupported derivation | Retained support references plus reverse dependency index and bounded affected-work traversal | Invalidation effective point, alternative supports, incomplete analysis and historical truth; automatic psychological belief replacement remains a separate choice |
| Acquisition/access | Explicit actual receipt and separately scoped grants/possession | Authorization before lookup/ranking, negative-result sealing, current access versus historical acquisition, no organizational union of knowledge |
| Generic processing | Small explicit transition table returning proposed changes/reasons | Actor/record grant checks, real input receipt, stable order, permission to request an action versus permission to perform it, partial/refusal behavior |
| Policy evaluation | Finite reviewed named predicates over supplied permitted inputs | No hidden world lookup; no free Python callback authority; policy/version/reason trace and domain separation |
| Persistence and replay | Selected future native Core contract, existing standard-library SQLite interface where approved | One semantic installer, exact immutable input capture, source/profile identity, atomic publication, retry, full cost/retention/rollback; no foreign tables in accepted C1 |
| Author diagnostics | Detached bounded machine-readable explanation with explicit viewer/cutoff | Privileged inspection versus holder projection, support/cause/rule identity, safe hidden/missing/denied outputs and no read-time acquisition |

Python 3.12 provides [deque](https://docs.python.org/3.12/library/collections.html#collections.deque), [heap queues](https://docs.python.org/3.12/library/heapq.html#priority-queue-implementation-notes) and [SQLite access](https://docs.python.org/3.12/library/sqlite3.html). These are building blocks, not Encounter contracts. In particular, bounded `deque(maxlen=...)` discards old items when full; do **not** mistake that for safe admission refusal or required-history retention. Explicit prechecks/counters are needed. Stable queue ties should use admitted semantic ordering, not object comparison or host arrival timing. A heap can also accumulate tombstones, which must count toward its actual bounded cost.

## Qualification and reconsideration rules

For any later optional dependency, require a small named adapter contract: immutable permitted input, pure result or disposable projection, explicit order and resource accounting, native IDs, no DB writer/callback authority, detached diagnostics and predictable absence behavior. No serialized library graph/machine/agenda becomes canonical continuation state. If an optional view is unavailable, report that feature unavailable without changing admitted meaning; do not silently choose an alternate inference policy.

A future adoption record must pin distribution/hash, exact LICENSE/NOTICE/vendored/transitive closure, selected extras, supported Windows/Python 3.12.0 behavior and advisory review. Run an independently specified equivalence/failure test before making replaceability claims. A library that is actually semantically required must fail before dependent admission if unavailable. The private baseline's lack of public redistribution permission remains unchanged.

Open evidence: root-owned disposable stdlib experiments can show whether a particular **scratch representation** handles their finite fixtures and costs. They cannot prove that a native successor is implemented, establish general workload capacity, compare uninstalled library performance, or close P0's optional dependency evidence gaps. This report does not preempt their measured results. Review actual spike artifacts before Gate A.

## Architecture cross-review checklist for E

Check the concrete candidate for duplicated generic libraries only after examining its actual finite needs. Require exact counts/work to justify a dependency; require a replaceable derived-view boundary; forbid engine-owned source truth, hidden callbacks, serialized canonical library state and direct writes around Core. A finite predicate/transition mechanism should not quietly grow into a custom general rule language. Preserve explicit routes to use a mature library if real authoring complexity later warrants one.
