# KeyWrapping substrate v0.1

**Version:** v0.1 · **Date:** 2026-10-22
**Status:** PROPOSED / NON-RUNTIME / NOT AN ACCEPTED SHARED CONTRACT
**Delivery:** local documentation package for owner review; no actual JSON Schema files, implementation or publication.

This package proposes the reusable semantic foundation beneath KeyWrapping: earned references, action meaning, grouped expression, versioned social commitments and sealed actor perspectives. It preserves Encounter's governing gameplay role while leaving accepted contracts, frozen packages, C1, C2.1 B0, Room Creator and ZANT unchanged.

The owner approved the research and specification work, the ten-role sequence and the local branch `docs/keywrapping-substrate-v0.1`. Actual schema files were deferred. Commit/push/merge/publication decisions remain separate. GitHub metadata reports public while historical repository prose describes private; the discrepancy is retained, not corrected here.

## Meaning of the examples

JSON appears inside Markdown as an explanation of candidate records and interactions. It is not a published wire format, a database migration, a validator or an installed shared schema. Example identifiers, field names, authored scenario policies and status labels remain proposed. Research examples may use their own schematic notation; the central JSON record family explains the integrated illustrative notation.

Canonical occurrences, internal identities and private diagnostics are privileged examples. Actor-facing views must be constructed from authorized acquisitions, rather than exposing those objects with cosmetic redaction. A shared reference is a handle for a subject; it is not a grant to inspect that subject's hidden facts.

## Review and acceptance limits

The owner should review the unresolved policies, action-sense gaps, audit dispositions and exact diff before any separate commit/publication decision. Documentation review does not grant design freeze, C2/B1 acceptance or runtime integration. Repository package checks preserve known product states; they do not exercise a KeyWrapping implementation, because none is supplied.

A paper test remains necessary before freezing the language or authorizing an implementation proof. It should test whether people enjoy composing, which senses and omissions they reach for, whether refusal/counterproposal is intelligible, and whether earned references feel useful. A syntactically valid JSON example cannot answer those questions.
